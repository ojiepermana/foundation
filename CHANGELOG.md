## [Unreleased]

### Added

- Kerangka Angular dan backend Elysia yang dapat dibuild melalui satu manifest root, dengan versi runtime serta dependency terkunci (spec 0001).
- Route status development lokal dan proxy frontend, dengan diagnostic serta dokumentasi development tidak tersedia pada komposisi production.
- Ekspor OpenAPI tanpa listener/database, pemeriksaan kontrak, generator SDK standalone, serta pemeriksaan reproduksibilitas dan drift artefak.
- Skenario APP-001 sampai APP-004, gate build/test, dan bukti 78 test lulus dengan review independen Approve. [Laporan bukti fitur 4](docs/testing/0001-application-structure.md) mencatat kandidat, JUnit, riwayat perbaikan, dan batas verifikasi.
- Infrastruktur PostgreSQL 18 development dari image proyek berbasis Oracle Linux 10 dan paket PGDG, dengan volume persisten, autentikasi SCRAM, dan credential administrator terpisah dari runtime aplikasi (spec 0002).
- Suite INFRA-001 sampai INFRA-006 untuk build terkunci, startup, koneksi, persistensi, penolakan key bundle/RPM unsigned, dan batas secret. [Laporan bukti fitur 3](docs/testing/0002-postgresql-development-infrastructure.md) mencatat hasil 18 test lulus dengan 168 assertion, bukti build kedua arsitektur, dan batas verifikasi.
- Provisioning PostgreSQL 18 yang membuat role owner, migrator, dan backend terpisah, tiga schema awal, serta metadata migration dengan privilege runtime minimum (spec 0004). [Laporan bukti fitur 5](docs/testing/0003-database-access.md) mencatat verifikasi runtime dan batas review.
- Perintah `db:migrate --apply` dan `db:seed --apply` yang terpisah dari startup aplikasi, dengan baseline metadata, checksum, transaksi, lock, dan penolakan file SQL yang tidak valid (spec 0005).
- Skenario MIG-001 sampai MIG-005 pada PostgreSQL 18 terisolasi, termasuk pengulangan, rollback, persaingan runner, dan batas akses role. [Laporan bukti fitur 6](docs/testing/0004-migration-seed.md) mencatat hasil dan batas verifikasinya.
- Shell Angular responsif dengan navigasi Kesiapan, skip link, dan dukungan keyboard pada desktop serta mobile (spec 0007).
- Batas resmi checker OpenAPI berupa tabel *Aturan checker* di spec 0008, dirujuk dari `docs/rules/openapi-sdk.md` bersama resep *Bentuk route yang diekspor bersih* untuk Elysia 1.4.30: model bernama untuk body dan response 2xx, `Type.Integer` dari `@sinclair/typebox` sebagai pengganti `t.Integer`, response 204 lewat `detail.responses`, serta `operationId`, satu tag, dan `security` pada `detail` setiap route (spec 0008).
- Fixture `tests/fixtures/openapi/subset-full.json` yang membuktikan bentuk yang diterima checker dibaca generator SDK dengan benar: checker menerimanya, `sdk:generate` berhasil, dan `tsc --strict` lulus untuk SDK hasil generate serta file konsumen (spec 0008).

Database yang tidak siap (pool tidak ada, koneksi ditolak atau terputus, hak `SELECT` dicabut, batas statement, atau batas jawaban 5.000 ms) dijawab 503 `{"status":"unavailable","checkedAt":...}`, dan request berikutnya kembali 200 setelah database pulih tanpa restart backend. Route tidak menulis database dan tidak mengirim nama, checksum, maupun waktu migration; kelengkapan migration tetap diperiksa `doctor` (spec 0006).

Komponen yang dipakai hanya `Card`, `Button`, dan `Spinner` dari entry point publik `@ojiepermana/angular`. Halaman `/` tetap pengantar statis tanpa request API (spec 0006).

- Preflight database nyata pada `bun run doctor`. Dengan role runtime dari `DATABASE_URL`, doctor memeriksa PostgreSQL minimal 18, nama database sesuai key baru `database.expectedName` di `config/development.json` (saat ini `foundation`), schema dari `database.schemas` dengan `USAGE` tanpa `CREATE`, tanpa `CREATE` pada `public`, serta role yang bukan superuser, tidak dapat membuat database, role, atau schema, dan tidak dapat menulis, memiliki, atau lewat keanggotaan role mengambil alih penulis `common.schema_migrations`. Doctor juga membandingkan nama dan checksum `SHA-256` seluruh file `database/migrations/*.sql` dengan `common.schema_migrations`: file yang belum diterapkan, metadata tanpa file, checksum berbeda, metadata yang tidak terbaca, direktori migration yang hilang, atau direktori tanpa file SQL membuat doctor gagal dengan exit code 1. Doctor tidak menulis database, tidak menjalankan migration atau seed, dan tidak menghentikan listener; `serve` juga tidak menjalankan migration otomatis (spec 0003).
- Lock invocation per checkout untuk `serve`. Direktori `.local/serve.lock` dibuat secara atomik sebelum doctor dan memuat `owner.json` (token acak, UID, checkout kanonik, PID dan waktu mulai OS supervisor, serta PID, waktu mulai, dan ID grup setiap layanan) yang ditulis lewat file sementara dan rename. `serve` kedua dari checkout yang sama gagal dengan `Serve lain dari checkout ini masih aktif.` tanpa menjalankan doctor dan tanpa mengganggu yang pertama. Catatan dari invocation yang sudah mati dipulihkan oleh satu pemulih lewat guard `serve.recovery.lock`, catatan baru yang belum lengkap ditunggu paling lama 5 detik, dan guard yang tersisa dari crash tidak diambil alih otomatis sehingga `serve` meminta penghentian manual (spec 0003).
- Readiness startup pada `serve`. Frontend berjalan pada `127.0.0.1:8889` dan backend pada `127.0.0.1:8888`, lalu baris `Frontend:` dan `Backend:` beserta `Layanan development siap.` baru dicetak setelah GET `/` memberi HTTP 200 berupa dokumen HTML dan GET `/api/status` memberi HTTP 200 dengan JSON `{"status":"ok"}`. Probe memakai GET tanpa redirect hanya ke `127.0.0.1`, dan pemegang port wajib terbukti milik grup proses baru invocation ini pada setiap probe dan tepat sebelum URL diumumkan. Seluruh layanan wajib siap dalam 60 detik sejak proses pertama dijalankan, diukur dengan monotonic clock lewat konstanta `STARTUP_TIMEOUT_MS` yang tidak dibaca dari environment; respons salah, listener asing, atau batas waktu menghentikan seluruh grup proses invocation ini dengan exit code bukan nol. Pemeriksaan HTTP ini hanya berlangsung saat startup; kesiapan database sesudahnya tetap dibuktikan lewat alur fitur 10 (spec 0003).
- Worker HTTP terpilih wajib mendeklarasikan `readinessPath` lokal di `config/development.json` (path absolut berawalan `/`, tanpa URL, query, atau fragment), dan `serve` menunggu HTTP 200 pada host serta port worker itu. `readinessPath` pada worker tanpa port ditolak, dan worker tanpa port dianggap siap selama prosesnya tetap hidup saat startup. - Gate CI tiga tier lewat runner `scripts/gate.ts` dengan tabel tier di `scripts/lib/gate.ts`: `bun run test:ci` (tier cepat, 17 langkah tanpa Docker), `bun run test:ci:real` (tier nyata: `test:infrastructure`, `test:database:real`, `test:database:migration`, `test:tooling:real`, dan `test:readiness:real` pada Docker, PostgreSQL 18 terisolasi, dan Chromium), serta `bun run test:ci:security` (`check:security`). Setiap langkah berjalan sebagai `bun --no-env-file run <script>` dalam grup proses sendiri dengan environment daftar izin, batas 600 detik per langkah pada tier cepat dan keamanan atau 1.500 detik pada tier nyata, dan masa tenggang 10, 90, atau 180 detik sesudah SIGTERM. Runner menghapus bukti lama sebelum langkah, berhenti pada langkah pertama yang tidak lulus dan mencatat sisanya `not_run` beserta kode alasannya, lalu menulis bundle `.local/feature-11/evidence/<tier>/` berisi salinan bukti (JUnit, screenshot, `image.json`, `artifact-scan.json`, atau `security.json`) dan `manifest.json` dengan commit, status bersih, `SHA-256` pohon sumber pada awal dan akhir tier, identitas run CI, versi Bun dan Node, OS, arsitektur, checksum input dan output, serta `SHA-256` setiap file bukti. Langkah gagal bila exit code bukan 0, waktu habis, bukti wajib hilang atau rusak, JUnit memuat failure atau error, atau `artifact-scan.json` memuat temuan. Langkah yang memuat testcase dilewati dicatat `skipped` dan membuat tier gagal, sehingga Docker yang tidak tersedia tidak pernah membuat tier nyata lulus. Pembaca JUnit `scripts/lib/junit.ts` tanpa dependency menolak `DOCTYPE`, entity tidak dikenal, elemen asing, `testcase` di luar `testsuite`, dan file di atas 50 MB. SIGINT, SIGTERM, dan SIGHUP menghentikan grup langkah, tetap menulis manifest, dan keluar 130, 143, atau 129; sesudah langkah tier cepat atau nyata dihentikan, PID yang masih mendengarkan port 8888 atau 8889 dicatat di `leftoverPorts` (spec 0010).
