## [Unreleased]

### Added

- Kerangka Angular dan backend Elysia yang dapat dibuild melalui satu manifest root, dengan versi runtime serta dependency terkunci (spec 0001).
- Route status development lokal dan proxy frontend, dengan diagnostic serta dokumentasi development tidak tersedia pada komposisi production.
- Ekspor OpenAPI tanpa listener/database, pemeriksaan kontrak, generator SDK standalone, serta pemeriksaan reproduksibilitas dan drift artefak.
- Skenario APP-001 sampai APP-004, gate build/test, dan bukti 78 test lulus dengan review independen Approve. [Laporan bukti fitur 4](docs/testing/0001-application-structure.md) mencatat kandidat, JUnit, riwayat perbaikan, dan batas verifikasi.
- Infrastruktur PostgreSQL 18 development dari image proyek berbasis Oracle Linux 10 dan paket PGDG, dengan volume persisten, autentikasi SCRAM, dan credential administrator terpisah dari runtime aplikasi (spec 0002).
- Suite INFRA-001 sampai INFRA-006 untuk build terkunci, startup, koneksi, persistensi, penolakan key bundle/RPM unsigned, dan batas secret. [Laporan bukti fitur 3](docs/testing/0002-postgresql-development-infrastructure.md) mencatat hasil 18 test lulus dengan 168 assertion, bukti build kedua arsitektur, dan batas verifikasi.
- Provisioning PostgreSQL 18 yang membuat role owner, migrator, dan backend terpisah, tiga schema awal, serta metadata migration dengan privilege runtime minimum (spec 0004). [Laporan bukti fitur 5](docs/testing/0003-database-access.md) mencatat verifikasi runtime dan batas review.
- Perintah `db:migrate --apply` dan `db:seed --apply` yang terpisah dari startup aplikasi, dengan baseline metadata, checksum, transaksi, lock, dan penolakan file SQL yang tidak valid (spec 0005).
- Skenario MIG-001 sampai MIG-005 pada PostgreSQL 18 terisolasi, termasuk pengulangan, rollback, persaingan runner, dan batas akses role. [Laporan bukti fitur 6](docs/testing/0004-migration-seed.md) mencatat hasil dan batas verifikasinya.
- Shell Angular responsif dengan navigasi Kesiapan, skip link, dan dukungan keyboard pada desktop serta mobile (spec 0007).
- Batas resmi checker OpenAPI berupa tabel *Aturan checker* di spec 0008, dirujuk dari `docs/rules/openapi-sdk.md` bersama resep *Bentuk route yang diekspor bersih* untuk Elysia 1.4.30: model bernama untuk body dan response 2xx, `Type.Integer` dari `@sinclair/typebox` sebagai pengganti `t.Integer`, response 204 lewat `detail.responses`, serta `operationId`, satu tag, dan `security` pada `detail` setiap route (spec 0008).
- Fixture `tests/fixtures/openapi/subset-full.json` yang membuktikan bentuk yang diterima checker dibaca generator SDK dengan benar: checker menerimanya, `sdk:generate` berhasil, dan `tsc --strict` lulus untuk SDK hasil generate serta file konsumen (spec 0008).
- Script `typecheck:contract` (`tsconfig.contract.json`, strict dengan `noUncheckedIndexedAccess`) untuk exporter, checker, `canonicalJson`, dan test kontrak, dijalankan oleh `test:ci`.
- Skenario OPENAPI-001 sampai OPENAPI-007 di registry `tests/scenarios/openapi-contract.json`, dengan matriks mutasi yang memberi setiap rule ID sedikitnya satu baris penolakan. [Laporan bukti fitur 8](docs/testing/0007-openapi-contract.md) mencatat 404 test OPENAPI lulus dengan 1.084 assertion, `test:integration` lulus 485 test, dan batas verifikasinya; [review ulang independen](docs/reviews/2026-10-03-main-openapi-contract-followup.md) memberi Approve with nits dengan tiga temuan minor tersisa.
- Konfigurasi SDK pada aplikasi Angular: `app.config.ts` memasang `provideHttpClient()` dan `provideApiConfiguration('')`, sehingga operasi SDK mengirim request same origin ke `/api/...` yang diteruskan proxy development. Initial bundle production naik dari 654,09 kB ke 675,94 kB karena `HttpClient` dan barrel `@sdk` kini masuk chunk awal; anggaran error 1 MB tetap terpenuhi (spec 0009).
- Harness backend nyata untuk `test:frontend`: satu proses backend Bun per run Vitest pada port loopback pilihan sistem operasi, tanpa `.env` dan tanpa `DATABASE_URL`, dengan nilai `sdkContractBackendUrl` dan `sdkContractClosedUrl` untuk test. Test `sdk-contract.integration.spec.ts` membuktikan request dan response `GET /api/status` melalui `DevelopmentService` dan `FoundationApi` terhadap backend nyata, termasuk 404 dan kegagalan jaringan berstatus 0. Karena itu `test:frontend` kini membutuhkan `bun` di `PATH` (spec 0009).
- Kontrak adapter fitur, batas impor SDK, cara kerja `api:check`, pemilik tunggal artefak, dan harness backend nyata kini tertulis di `docs/rules/openapi-sdk.md`, dengan rujukan dari `docs/rules/angular.md`. Kontrak itu menjadi pegangan fitur 10 saat membangun adapter pertama: satu adapter `<fitur>-api.ts` per area fitur, tanpa `HttpClient` atau URL tulisan tangan, dan `HttpErrorResponse` dipetakan ke tipe milik fitur (spec 0009).
- Skenario SDK-001 sampai SDK-010 di registry `tests/scenarios/sdk-contract.json`. [Laporan bukti fitur 9](docs/testing/0008-sdk-contract.md) mencatat 54 test SDK lulus dengan 608 assertion, `test:integration` lulus 588 test dengan 2.071 assertion, 7 test frontend, `test:ci` lulus, pin locale yang juga terbukti di kontainer Linux aarch64, dan batas verifikasinya; [review ulang independen](docs/reviews/2026-10-03-main-sdk-contract-followup.md) memberi Approve with nits dengan lima nit tersisa.

### Changed

- Proses backend dan worker dari `serve` tidak menerima credential administrator atau migrator dari environment development.
- Perintah pembaruan image PostgreSQL development menjalankan ulang instalasi paket PGDG meski base image tetap sama (spec 0002).
- Checker OpenAPI kini berupa allow list dengan 16 rule ID yang diperiksa menurut urutan tabel spec dan berhenti pada pelanggaran pertama, sehingga satu dokumen selalu melaporkan rule ID yang sama. Bentuk yang tidak tercantum ditolak, termasuk versi `3.0.3`, `servers`, reference eksternal atau nama telanjang, `anyOf`, nullable, `oauth2`, parameter cookie atau array, dan response `default`. Operasi `GET /api/status` diperiksa lewat `REQUIRED_OPERATIONS`, yang hanya bertambah melalui spec fitur pemilik route (spec 0008).
- Setiap operasi OpenAPI wajib mendeklarasikan `security` sendiri, termasuk `security: []` untuk route publik. `security` dokumen tidak lagi diwarisi, sehingga route terlindungi yang lupa `detail.security` tidak lolos sebagai publik (spec 0008).
- Ekspor OpenAPI mengurutkan key menurut code unit lewat `canonicalJson`, sehingga `openapi.json` tidak bergantung pada locale mesin, lalu menulis lewat file sementara dan rename. Ekspor yang gagal, termasuk exception saat import route atau `createApp()`, berakhir dengan exit code 1, hanya mencetak `OpenAPI export failed` ditambah `rule: <ID>` untuk pelanggaran kontrak, dan meninggalkan `openapi.json` tanpa perubahan. `openapi.json` dan SDK hasil generate tetap byte identik (spec 0008).
- Validator `api:validate` menerima paling banyak satu path dan menolak teks berawalan byte order mark, seperti generator SDK. Kegagalan hanya mencetak `OpenAPI validation failed`, ditambah `rule: <ID>` untuk pelanggaran kontrak (spec 0008).
- `api:check` tidak lagi menjalankan `api:sync` pada checkout. Pemeriksaan kini meregenerasi `openapi.json` dan SDK dua kali dari keadaan kosong di direktori sementara, membandingkan run pertama dengan run kedua lebih dulu, lalu checkout dengan hasil regenerasi byte demi byte, tanpa cache dan tanpa git. Setiap perbedaan disebut per file sebagai baris `added`, `changed`, atau `removed`, disusul `OpenAPI or SDK generation is not repeatable` atau `OpenAPI or SDK drift detected` dan exit code 1. File di folder SDK yang tidak dibuat generator, termasuk `.DS_Store`, kini dilaporkan `removed` dan dihapus manual oleh pemilik artefak (spec 0009).
- Setiap `api:sync` di dalam `api:check` berjalan dalam process group sendiri dengan batas 120 detik. Batas waktu, SIGINT, dan SIGTERM menghentikan seluruh group (SIGTERM, lalu SIGKILL sesudah 5 detik) sebelum direktori sementara dihapus, sehingga tidak ada proses maupun folder sementara yang tertinggal. Batas waktu berakhir dengan `API synchronization failed`, sedangkan SIGINT dan SIGTERM memberi exit code 130 dan 143 (spec 0009).
- Script `sdk:generate` mempin `LC_ALL=en_US.UTF-8`, karena generator mengurutkan operasi menurut locale proses. Tanpa pin, urutan di `public-api.ts` dan service berbeda antara locale `cs_CZ` dan `en_US`; dengan pin hasilnya byte identik di macOS dan Linux. Artefak tersimpan tidak berubah (spec 0009).
- `check:frontend:bundle` kini memeriksa seluruh `apps/frontend/src`, bukan hanya `src/app`, dan mengganti larangan `@sdk` menyeluruh dengan tabel *Bentuk impor SDK*. `@sdk` hanya diterima di `app.config.ts` dan adapter `src/app/features/<fitur>/<fitur>-api.ts` dalam bentuk impor bernama (adapter juga boleh `export type { ... } from '@sdk'`), sedangkan `@sdk/...`, impor dinamis, `require`, ekspor ulang nilai SDK, dan path relatif ke folder SDK ditolak. Kegagalan mencetak satu baris pesan tetap ke stderr dengan exit code 1, tanpa stack atau potongan source (spec 0009).
- `typecheck:contract` kini juga memeriksa script `api:check`, checker bundle, modul `scripts/lib` yang dipakai keduanya, dan file harness Vitest (spec 0009).

### Security

- Build PostgreSQL mewajibkan digest dan signature RPM yang valid dari key PGDG terverifikasi sebelum memasang repo; RPM tanpa signature ditolak (spec 0002).
- Fingerprint penuh setiap sertifikat public key PGDG divalidasi sebelum import global; bundle dengan key tambahan ditolak. GnuPG dan dependency paket sementara dihapus setelah verifikasi. Helper produksi juga menolak signature rusak dan signature valid dari key tepercaya lain; fixture memastikan payload dan scriptlet tidak dijalankan sebelum pemeriksaan selesai (spec 0002).
- Script `api:openapi` dan `api:validate` berjalan dengan `bun --no-env-file`, sehingga `.env` checkout yang memuat secret aplikasi tidak masuk proses yang memuat komposisi backend. Pesan kegagalan ekspor dan validasi tidak memuat isi dokumen, path file, pesan parser, atau stack, sehingga isi itu tidak bocor ke log CI (spec 0008).
- Validator hanya membaca file biasa sampai 8 MiB, sehingga direktori, FIFO, `/dev/zero`, dan file sparse 1 GiB ditolak. Kedalaman schema dibatasi 32 tingkat dan diperiksa saat turun, sedangkan deteksi siklus reference memakai stack eksplisit, sehingga rantai `items` 200.000 tingkat ditolak dengan rule `schema` tanpa `RangeError`. Batas ini menjaga konsumsi resource tetap terbatas saat CI memeriksa kontrak dari branch mana pun (spec 0008).
- `api:check` berjalan dengan `bun --no-env-file`, dan setiap tahap regenerasi hanya menerima `PATH` serta `HOME`. Salinan input tidak memuat file bernama `.env` atau `.env.*` di level mana pun. Symlink input hanya diterima bila targetnya relatif kanonik di dalam root checkout tanpa melewati `node_modules`; target absolut, target yang keluar dari root, `../node_modules/../.env`, dan input yang segmen induknya berupa symlink membuat pemeriksaan gagal dengan `API check failed` sebelum regenerasi dimulai (spec 0009).
- `api:check` membaca checkout dengan `lstat` tanpa mengikuti symlink, tidak pernah membuka file tanpa pasangan atau berbeda ukuran, membandingkan file berukuran sama lewat hash `SHA-256` streaming, dan tidak mencetak isi file. Path di luar karakter aman ditulis sebagai literal berkutip dengan escape `\uXXXX`, baik pada laporan `api:check` maupun pesan `check:frontend:bundle`, sehingga nama file berisi newline tidak dapat menambah baris palsu, misalnya perintah `::error::`, pada log CI (spec 0009).
- `check:frontend:bundle` menolak symlink di bawah `apps/frontend/src` dan `apps/frontend/dist`, karena checker tidak mengikutinya sedangkan build Angular mengikutinya (spec 0009).
- Harness backend test tidak meneruskan credential dari environment induk maupun `.env`: backend hanya menerima `PATH`, `HOME`, `NODE_ENV`, `HOST`, dan `PORT`, hanya mendengar pada `127.0.0.1`, dan output child dibuang (spec 0009).
