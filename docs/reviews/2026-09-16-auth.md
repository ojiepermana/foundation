The two findings from the first review pass are resolved. ## Resolved Findings
### ✅ Passkey login no longer bypasses password reauthentication, `server/auth.ts:262`
**Resolution**: `issueSession()` now requires an explicit `passwordAuthenticated` boolean. Password login and password change pass `true`; passkey login passes `false`, which stores an epoch `reauthenticated_at` value. `database/migrations/0002_password_reauth_default.sql` also changes the default to the same expired epoch for existing databases.

### ✅ User listing rechecks the current admin role, `server/auth.ts:157`
**Resolution**: `listUsers()` now runs inside a transaction, calls `lockIdentity()`, and asserts the locked actor is still an admin before issuing the list/count queries.

## Strengths
- Sensitive token material is stored as SHA-256 digests, session cookies are HttpOnly/SameSite and Secure on HTTPS, and CSRF comparison uses a constant-time comparison.
- Activation/reset token consumption and session revocation happen in transactions, and the last-active-admin mutation path uses a transaction advisory lock plus row locks to protect concurrent demotion/disable attempts.
- Auth rate limiting uses Redis atomic increments and returns a 503 on limiter outage instead of silently allowing auth attempts through.
