### 🟠 File key dapat menyuntikkan signer tambahan ke trust store, `infrastructure/postgres/verify-pgdg-repo-rpm.sh:25`

**Problem**: Baris 18 sampai 22 hanya memeriksa fingerprint paket public key pertama. Baris 25 kemudian mengimpor seluruh file asli, dan baris 27 hanya memastikan key PGDG ada. File yang berisi armor key PGDG asli diikuti armor key penyerang lolos fingerprint dan mengimpor keduanya. Repo RPM asli tetap lolos pemeriksaan signer PGDG, sehingga helper selesai dengan exit 0 dan meninggalkan key tambahan di trust store global RPM.

**Why it matters**: Instalasi paket di `infrastructure/postgres/Dockerfile:41` memakai `microdnf` dan trust store tersebut. `gpgcheck=1` tidak membatasi signature ke key pada opsi repo `gpgkey` apabila key lain sudah dipercaya RPM. Pihak yang dapat mengganti unduhan key dan menyajikan paket dari sumber unduhan dapat mempertahankan repo RPM asli, menambahkan key sendiri, lalu memasukkan paket bertanda tangan sendiri. Fingerprint PGDG yang dikunci tidak lagi membatasi kepercayaan rantai pasok. Ini merupakan cacat yang direproduksi, bukan sekadar kekurangan bukti atau dugaan benturan ID key.

**Evidence**: Reviewer menjalankan dua probe dengan `docker run --rm -i --user 0` pada base yang dipin, `oraclelinux:10-slim@sha256:0660af1f1bb56559b299d99d3b71d0ff51f9d593cecbd3154a46914704ec34d6`. Helper kandidat di mount sebagai read only. Semua key privat fixture, RPM, repo, payload, dan penanda berada di container yang langsung dihapus.

1. Ambil public key arm64 PGDG dan repo RPM resmi. Buat key RSA fixture melalui GnuPG, lalu gabungkan file dengan `cat /tmp/pgdg.key /tmp/extra.key > /tmp/bundle.key`.

Pemeriksaan keberadaan delapan karakter ID tidak cukup untuk memastikan tidak ada key lain yang ikut masuk.
