# 0008. Ekspor dan pemeriksaan kontrak OpenAPI

**Date**: 2026-10-03
**Status**: Accepted

## Summary

Exporter dan checker Bun yang sudah ada tetap menjadi gerbang antara route Elysia dan generator SDK Angular. Checker hanya menerima bentuk OpenAPI yang diekspor Elysia secara bersih dan dibaca generator SDK dengan benar; bentuk lain ditolak dengan rule ID yang jelas, bukan dibiarkan lolos lalu rusak di SDK. Rule diperiksa menurut urutan tabel, sehingga satu dokumen selalu menghasilkan rule ID yang sama. Urutan key ekspor dibuat tidak bergantung pada locale, input CLI dan waktu pemeriksaan dibatasi, dan batas checker ditulis sebagai tabel aturan. Kelulusan checker bukan sertifikasi penuh OpenAPI.

## Requirements

**User stories**:
- Sebagai pengembang, saya ingin kontrak API diekspor dari komposisi backend yang nyata dan diperiksa sebelum SDK dibuat, agar SDK tidak pernah dihasilkan dari kontrak yang rusak atau yang tidak dapat dibaca generator.
- Sebagai pengembang, saya ingin tahu aturan mana yang dilanggar dan apa batas checker, agar saya dapat memperbaiki route tanpa menebak dan tidak menganggap kelulusan sebagai sertifikasi penuh OpenAPI.

**Acceptance criteria**:
- **AC-1**: `bun run api:openapi` menjalankan `scripts/export-openapi.ts`, yang memuat komposisi backend melalui `await import()` di dalam blok penanganan kegagalan, membuat `createApp('development')`, membaca `/openapi/json` melalui `app.handle()`, memeriksa hasilnya dengan checker yang sama, lalu menulis `openapi.json` di root. Dalam subprocess dengan guard preload yang mengganti `Bun.serve`, `Bun.listen`, `Bun.connect`, `Bun.udpSocket`, `Bun.SQL`, `Bun.sql`, `fetch`, `WebSocket`, `connect` dan `createConnection` dari `node:net`, serta `connect` dari `node:tls`, dan dengan `DATABASE_URL` sentinel yang menunjuk listener TCP milik test, ekspor berhasil, tidak ada guard yang terpanggil, dan listener sentinel tidak menerima koneksi.
- **AC-2**: Hasil ekspor deterministik. `canonicalJson(value)` menulis teks secara rekursif dari array key terurut `Object.keys(value).sort()` (urutan code unit UTF-16, bukan locale), bukan dari object yang dibangun ulang, karena object JavaScript selalu menaruh key bilangan bulat seperti `9` dan `10` lebih dulu. Key dan nilai skalar ditulis dengan `JSON.stringify`, urutan array dipertahankan, tata letaknya sama dengan `JSON.stringify(value, null, 2)` (`": "` sesudah key, array dan object kosong tetap `[]` dan `{}`), teks diakhiri satu newline, dan key `__proto__` diperlakukan sebagai key biasa. Unit test pada hasil `JSON.parse` dengan key `_x`, `$ref`, `A`, `a`, `10`, `9`, dan `__proto__` menghasilkan urutan tepat `$ref`, `10`, `9`, `A`, `__proto__`, `_x`, `a`, dan `canonicalJson(JSON.parse(teks))` sama dengan teks `openapi.json` yang tersimpan. Dua ekspor berurutan menghasilkan byte identik dan sama dengan file tersimpan. Dokumen hasil ekspor tidak mempunyai key `servers`, dan `openapi.json`, stdout, serta stderr ekspor tidak memuat `localhost` maupun nilai sentinel environment yang diberikan test.
- **AC-3**: Checker menerima `openapi.json` hasil ekspor saat ini dan fixture `tests/fixtures/openapi/valid.json`. Checker menjalankan rule menurut urutan baris tabel *Aturan checker*, berhenti pada pelanggaran pertama, dan melempar `OpenApiContractError` yang properti `rule` berisi rule paling atas yang dilanggar dokumen. Matriks mutasi menolak pelanggaran setiap klausa rule `document`, `version`, `info`, `path`, `method`, `operation`, `operation-id`, `tag`, `parameter`, `request-body`, dan `response` dengan rule ID yang diharapkan, termasuk `servers`, versi `3.0.3`, path dengan `?` atau kurung kurawal tanpa pasangan, `trace`, `parameters` tingkat path item, `operationId` dengan tanda hubung atau duplikat, dua tag, tag yang tidak dideklarasikan, parameter cookie, parameter array, nama parameter yang sama di path dan query, parameter bernama `body`, body JSON inline, response 200 inline, response `default`, serta operasi dengan dua response 2xx atau tanpa response 2xx.
- **AC-4**: Checker menolak pelanggaran rule `component`, `schema`, dan `reference` dengan rule ID yang diharapkan. Kasus wajibnya: reference eksternal atau relatif (`https:`, `file:`, `./x.json`, dan nama telanjang `Item` seperti keluaran `t.Ref` Elysia), reference ke section selain `components.schemas`, target yang tidak ada, siklus langsung lewat properti dan siklus tidak langsung, `$ref` dengan key lain di sampingnya, `$id` di schema bersarang, `anyOf` yang dihasilkan `t.Integer` Elysia, kedua bentuk nullable (`nullable: true` dan `type` berupa array dengan `null`), `additionalProperties` berupa schema, `default` berupa object, `required` yang menyebut `constructor` tanpa properti milik sendiri, properti bernama `__proto__`, dan schema 33 tingkat; schema 32 tingkat diterima. Rantai `items` sedalam 200.000 tingkat di bawah 8 MiB ditolak dengan rule `schema`, bukan `RangeError`. Dokumen kisi 40 tingkat yang setiap komponennya merujuk komponen tingkat berikutnya dua kali diterima dalam kurang dari satu detik, dokumen yang sama dengan satu rujukan balik ditolak dengan rule `reference` dalam kurang dari satu detik, dan rantai 20.000 komponen diterima tanpa `RangeError`.
- **AC-5**: Checker menolak pelanggaran rule `security` dan `required-operation` dengan rule ID yang diharapkan. Kasus `security`: operasi tanpa `security` sendiri, termasuk saat `security` dokumen bernilai `[]` atau memuat requirement yang valid, requirement berupa object kosong, scheme yang tidak dideklarasikan termasuk nama warisan seperti `constructor`, requirement `http` atau `apiKey` dengan scope tidak kosong, scheme `oauth2` atau `openIdConnect`, dan `security` dokumen yang tidak valid walau semua operasi menimpanya. Kasus `required-operation` memakai mutasi yang hanya melanggar rule itu: operasi `GET /api/status` dihapus sementara operasi valid lain tetap ada, `operationId` diganti nama valid lain, tag diganti tag lain yang dideklarasikan, `const` dan `enum` diganti bersama menjadi `bad`, properti tambahan, serta operasi status yang memerlukan scheme `http` bearer yang dideklarasikan dengan `[]`. Checker mengekspor `REQUIRED_OPERATIONS` yang berisi tepat entri *Tabel operasi wajib*, sehingga fitur lain menambah entri melalui spec miliknya. `app.handle()` untuk `GET /api/status` tanpa credential memberi 200 dengan body `{"status":"ok"}`; bukti otorisasi route lain tetap milik spec fitur pemilik route.
  - *Amandemen 2026-10-06 (spec [0014](../0014-akses-pengguna-lifecycle-sesi/index.md), tabel Operasi wajib baru)*: `REQUIRED_OPERATIONS` bertambah tiga entri (`signIn`, `getAuthSession`, `listAuthSessions`), masing masing dengan mutasi yang hanya melanggar entri itu dan ditolak `required-operation`. Tabel *Aturan checker* tidak berubah. Resep *Ekspor route 204 dengan galat* spec 0014 (semua status di `detail.responses` tanpa map `response`) melengkapi resep 204 tanpa galat spec ini.
- **AC-6**: Kontrak output berikut berlaku untuk proses script, yaitu `bun --no-env-file scripts/validate-openapi.ts [path]` dan `bun --no-env-file scripts/export-openapi.ts`. Baris yang dicetak pembungkus `bun run` (`$ bun ...` dan `error: script ... exited with code 1`) berada di luar kontrak dan hilang dengan `bun run --silent`. Validator memakai `openapi.json` root bila tanpa argumen, memperlakukan satu argumen sebagai path apa pun awalannya, menolak lebih dari satu argumen, memeriksa dengan `stat` bahwa path adalah file biasa sebelum membuka, dan membaca paling banyak 8.388.608 byte (8 MiB) ditambah satu byte. Kontrak valid yang diberi padding spasi sampai tepat 8.388.608 byte diterima; isi yang sama sebesar 8.388.609 byte ditolak tanpa baris `rule:`; file sparse 1 GiB ditolak sebelum batas kill test. Argumen berlebih, file hilang, direktori, `/dev/zero`, FIFO, file terlalu besar, JSON rusak, teks yang diawali byte order mark UTF-8 (ditolak `JSON.parse` generator SDK), atau kontrak tidak valid berakhir dengan exit code 1. Stderr validator berisi tepat baris `OpenAPI validation failed`, ditambah baris kedua `rule: <ID>` hanya untuk pelanggaran kontrak, tanpa isi dokumen, path file, pesan parser, atau stack. Kegagalan ekspor, termasuk exception saat import modul route, rejection atau exception timer tanpa jeda yang ditinggalkan modul route saat diimpor, exception di `createApp()`, respons `/openapi/json` yang bukan 200 atau bukan JSON, pelanggaran kontrak, dan teks kanonik lebih dari 8.388.608 byte UTF-8, mencetak tepat `OpenAPI export failed` dengan baris `rule: <ID>` hanya untuk pelanggaran kontrak, berakhir dengan exit code 1, dan meninggalkan `openapi.json` byte identik tanpa mengganti file (inode tetap) dan tanpa file sementara. Script root `api:openapi` dan `api:validate` menjalankan proses yang sama dengan `bun --no-env-file`, sehingga `.env` checkout tidak masuk proses. Pada workspace terisolasi dengan route status nyata yang diubah sehingga melanggar aturan, `bun run api:sync` berakhir nonzero, `sdk:generate` tidak berjalan, dan isi `apps/frontend/sdk/` byte identik.
- **AC-7**: Fixture `tests/fixtures/openapi/subset-full.json` memuat operasi status wajib dan bentuk berikut: tujuh method; parameter `path`, `query`, dan `header` bertipe `string`, `integer`, `number`, dan `boolean`, termasuk `enum` string pada query dan nama header bertanda hubung; body JSON `$ref` dengan `required: true` dan tanpa `required`, ditambah media type form yang diekspor Elysia; response 200 `$ref`, response `204` tanpa `content`, dan response 4xx dengan schema inline; komponen `object` yang memakai setiap keyword schema yang diterima tabel, komponen `array`, komponen enum `string`, `integer`, dan `number`, `const`, serta `$ref` bersarang pada `properties` dan `items`; operasi `deprecated`; serta scheme `http` bearer dan `apiKey` di `header`, `query`, dan `cookie`. Checker menerimanya, `sdk:generate` berhasil di workspace terisolasi dengan fixture itu sebagai `openapi.json`, dan `tsc --strict` lulus untuk SDK hasil generate serta file konsumen yang memakai tipe body, parameter, dan response, termasuk `@ts-expect-error` untuk nilai yang salah. Route uji yang ditambahkan in-process pada `createApp('development')` dengan resep 204 (`detail.responses` berisi `{ 204: { description } }` tanpa schema `response[204]`) diekspor tanpa `content` dan diterima checker. Klaim bahwa bentuk yang lolos checker dapat dibaca generator hanya berlaku untuk bentuk yang tercantum di AC ini.
- **AC-8**: Tabel *Aturan checker* pada spec ini adalah pernyataan resmi batas checker. Komentar pembuka `scripts/validate-openapi.ts` dan bagian ekspor pada `docs/rules/openapi-sdk.md` merujuk spec ini dan menyatakan bahwa kelulusan bukan sertifikasi penuh OpenAPI atau JSON Schema; bagian itu juga memuat *Bentuk route yang diekspor bersih*. Test membaca baris tabel tepat sesudah baris `**Aturan checker**` sampai baris kosong pertama, melewati baris judul dan pemisah, mengambil ID dari teks di antara backtick pada sel pertama, dan membuktikan urutannya sama persis dengan `OPENAPI_RULE_IDS`; setiap rule ID mempunyai sedikitnya satu baris penolakan di matriks mutasi. Tidak ada dependency, variable environment aplikasi, secret, atau perubahan database baru.

## Decision

**Chosen option**: Perbaiki exporter dan checker Bun yang sudah ada, dengan subset aturan yang ditentukan oleh perilaku nyata exporter Elysia dan generator SDK terpasang.

Command `api:openapi`, `api:validate`, `api:sync`, dan `api:check` tetap sama. Checker berubah dari pemeriksaan longgar menjadi allow list (daftar bentuk yang diizinkan): setiap key dan keyword di luar tabel aturan ditolak, dan rule diperiksa menurut urutan tabel sehingga rule ID yang dilaporkan pasti. Versi yang diterima hanya `3.1.0`. Checker tidak memakai validator eksternal dan tidak mengubah `scripts/check-api.ts`; drift dan manifest SDK tetap milik fitur 9.

## Feature design

**Data model sketch**: Tidak ada data persisten, schema database, migration, seed, atau role database. Fitur ini tidak membutuhkan keputusan schema.

|---|---|

Dengan begitu segmen kosong, segmen titik, garis miring akhir, `?`, `#`, spasi, dan kurung kurawal tanpa pasangan ditolak. Nama template tidak berulang dalam satu path. | `operation-id` | `operationId` wajib ada, cocok dengan `^[a-z][a-z0-9]*([A-Z][a-z0-9]+)*$`, dan unik pada seluruh dokumen. |
| `tag` | `tags` dokumen berupa array object yang hanya memuat `name` dan `description` string opsional. `name` cocok dengan `^[a-z][a-z0-9]*(-[a-z][a-z0-9]*)*$` dan unik. Setiap operasi mempunyai `tags` berisi tepat satu nama yang dideklarasikan pada `tags` dokumen. |
| `parameter` | `parameters` operasi berupa array. Parameter berupa object inline tanpa `$ref` dengan `name` string tidak kosong, `in` bernilai `path`, `query`, atau `header`, dan `schema` wajib; `required` boolean dan `description` string opsional. `name` unik di seluruh parameter satu operasi tanpa membedakan huruf besar dan kecil, dan nama `body` ditolak karena SDK memakainya untuk body. Parameter `path` wajib `required: true` dan berpasangan dua arah dengan template path. `cookie`, `content`, `style`, `explode`, `allowEmptyValue`, `deprecated`, schema `array` atau `object`, dan key lain ditolak. |
| `request-body` | `requestBody` berupa object inline tanpa `$ref` yang hanya memuat `content`, serta `required` boolean dan `description` string opsional. `content` memuat `application/json` yang schemanya object reference. Media type lain, misalnya `application/x-www-form-urlencoded` dan `multipart/form-data` yang selalu diekspor Elysia untuk body object, boleh ada. Setiap key media type cocok dengan `^[a-z0-9][a-z0-9.+-]*/[a-z0-9][a-z0-9.+-]*$`, dan nilainya object yang hanya memuat `schema` wajib. |
| `response` | `responses` wajib ada dan berupa object dengan key tiga digit `100` sampai `599` dan tepat satu key 2xx. Response berupa object inline tanpa `$ref` yang hanya memuat `description` string tidak kosong dan `content`. Response `204` tidak mempunyai `content`; response lain mempunyai `content` dengan sedikitnya satu media type yang bentuknya sama seperti pada `request-body`. Response 2xx selain `204` memuat `application/json` yang schemanya object reference. `default`, `headers`, `links`, dan key lain ditolak. |
| `component` | `components` berupa object yang hanya memuat `schemas` dan `securitySchemes`, masing masing berupa object. Nama schema komponen cocok dengan `^[A-Z][a-z0-9]+([A-Z][a-z0-9]+)*$`. Root schema komponen adalah schema konkret tanpa `$ref` dengan `type` `object` atau `array`, atau `type` `string`, `integer`, atau `number` yang mempunyai `enum`. `$id` di root komponen opsional dan bernilai tepat `#/components/schemas/<Nama>` komponen itu. | `schema` | Schema konkret mempunyai `type` string tunggal: `string`, `integer`, `number`, `boolean`, `object`, atau `array`. Keyword untuk semua tipe: `type`, `title`, `description`, `default`, `example`, `examples`, `deprecated`, `readOnly`, dan `writeOnly`, ditambah `$id` khusus di root komponen. `title` dan `description` berupa string; `deprecated`, `readOnly`, dan `writeOnly` berupa boolean; `default` dan `example` berupa skalar JSON (string, angka finite, atau boolean); `examples` berupa array skalar JSON. Nilai `default`, `example`, dan `examples` tidak ditelusuri dan tidak dicocokkan dengan `type`. `string` menambah `format` (string tidak kosong), `pattern` (dapat dikompilasi `new RegExp(pattern)`), serta `minLength` dan `maxLength` (integer nonnegatif, min tidak melebihi max). `integer` dan `number` menambah `minimum` dan `maximum` (angka finite, min tidak melebihi max). `object` menambah `properties` (object dengan key string tidak kosong selain `__proto__` dan nilai berupa schema), `required` (array nama unik yang masing masing own property `properties`), dan `additionalProperties` (boolean). `array` wajib mempunyai `items` berupa schema. `enum` dan `const` hanya untuk `string`, `integer`, dan `number`: `enum` adalah array tidak kosong berisi nilai unik yang sesuai tipe, `const` adalah satu nilai yang sesuai tipe, dan bila keduanya ada maka `enum` tepat berisi `[const]`. Nilai `integer` harus bilangan bulat. Kedalaman satu pohon schema paling banyak 32 tingkat: root bernilai 1, setiap masuk ke nilai `properties` atau `items` menambah satu tingkat, dan kedalaman diperiksa saat turun sehingga tingkat 33 langsung ditolak tanpa penelusuran lebih jauh. Object reference tidak diperiksa atau ditelusuri rule ini. Keyword lain ditolak, termasuk `anyOf`, `oneOf`, `allOf`, `not`, `nullable`, `type` berupa array, `patternProperties`, `$defs`, `$id` di luar root komponen, `multipleOf`, `exclusiveMinimum`, `exclusiveMaximum`, `minItems`, `maxItems`, `uniqueItems`, dan key `x-`. |
| `reference` | Object reference hanya muncul di posisi schema yang mengizinkannya (schema media type `requestBody` dan response, nilai `properties`, dan `items`), hanya memuat key `$ref`, dan `$ref` bernilai tepat `#/components/schemas/<Nama>` menuju komponen yang ada sebagai own property. Reference eksternal, relatif, nama telanjang, ke section lain, pointer rusak, target hilang, dan siklus reference antarkomponen lewat `properties` atau `items`, termasuk komponen yang merujuk dirinya sendiri, ditolak. |
| `security` | `security` dokumen, bila ada, dan `security` operasi berupa array. Setiap operasi mendeklarasikan `security` sendiri; `security` dokumen tidak diwarisi, sehingga route terlindungi yang lupa `detail.security` tidak lolos sebagai publik. Array kosong berarti publik. Setiap requirement, termasuk pada `security` dokumen walau semua operasi menimpanya, adalah object tidak kosong yang setiap key berupa nama own property di `components.securitySchemes` dan setiap nilai tepat array kosong `[]`. Security scheme berupa object inline tanpa `$ref`: `type: "http"` dengan `scheme` string tidak kosong serta `bearerFormat` dan `description` string opsional, atau `type: "apiKey"` dengan `name` string tidak kosong, `in` bernilai `header`, `query`, atau `cookie`, dan `description` string opsional. `oauth2`, `openIdConnect`, `mutualTLS`, dan key lain ditolak. |
| `required-operation` | Setiap entri `REQUIRED_OPERATIONS` ada di dokumen: path dan method entri, `operationId` dan tag entri, `security` yang dideklarasikan langsung pada operasi sama dengan entri, response dengan status sukses entri yang memuat `application/json` `$ref` ke komponen entri, dan komponen itu lulus asersi schema entri. |

**Urutan evaluasi dan pembagian rule**:
- Checker menjalankan rule menurut urutan baris tabel. Setiap rule memeriksa seluruh dokumen sebelum rule berikutnya berjalan, dan checker berhenti pada pelanggaran pertama. Karena itu rule ID yang dilaporkan selalu rule paling atas yang dilanggar dokumen, apa pun urutan key dokumen, dan rule yang lebih bawah boleh mengandalkan struktur yang sudah dijamin rule di atasnya.
- Pohon schema yang diperiksa rule `schema` dimulai dari `schema` parameter, `schema` media type `requestBody` dan response, dan root setiap komponen, lalu turun ke nilai `properties` dan `items`.
- `$ref` di posisi bukan schema (root dokumen, path item, operasi, parameter, `requestBody`, response, media type, security scheme, dan root komponen) adalah key yang tidak diizinkan rule pemilik posisi itu, bukan pelanggaran `reference`.
- Object schema yang mempunyai key `$ref` adalah object reference. Rule `schema` tidak memeriksa atau menelusurinya; key samping, bentuk pointer, target, dan siklus seluruhnya milik `reference`.
- `$id` di root komponen diperiksa `component`; `$id` di bagian lain pohon schema adalah keyword yang tidak dikenal bagi `schema`.
- String tidak kosong berarti `value.trim().length > 0`. Semua key dibaca sebagai own property, dan registry yang dikunci string dari dokumen memakai `Map` atau `Set`.
- Setiap kasus di matriks mutasi menyebut rule ID yang diharapkan menurut urutan ini. Mutasi `required-operation` disusun agar tidak melanggar rule lain lebih dulu, misalnya mengganti `const` dan `enum` bersama, bukan hanya `enum`.

**Tabel operasi wajib** (disimpan sebagai data `REQUIRED_OPERATIONS` di checker; entri baru ditetapkan spec fitur pemilik route):

| Path | Method | `operationId` | Tag | Security operasi | Response sukses | Sumber |
|---|---|---|---|---|---|---|

Setiap entri `REQUIRED_OPERATIONS` berbentuk object readonly dengan field `path`, `method`, `operationId`, `tag`, `security` (array requirement yang dibandingkan secara struktural), `successStatus` (misalnya `'200'`), `component` (nama komponen response sukses), dan `checkComponent` (fungsi murni yang menerima schema komponen dan mengembalikan boolean).

**Bentuk route yang diekspor bersih** (resep yang terbukti dengan Elysia 1.4.30 dan `@elysia/openapi` 1.4.16; ditulis ke `docs/rules/openapi-sdk.md` pada build plan langkah 5):
- Model body dan response 2xx didaftarkan dengan `.model({ Nama: schema })` lalu dirujuk dengan string nama pada `body` atau `response`, sehingga diekspor sebagai `#/components/schemas/Nama`.
- Bilangan bulat memakai `Type.Integer` dari `@sinclair/typebox` yang sudah dipin, bukan `t.Integer` atau `t.Numeric`.
- Route tidak memakai `t.Nullable`, union campuran tipe, `t.Ref` di dalam model, `t.Array(t.Ref(...))`, atau `t.Array` berisi schema ber `$id`, karena keluarannya `anyOf`, nullable, nama telanjang, atau `$id` bersarang.
- Response 204 dideklarasikan dengan `detail.responses` berisi `{ 204: { description } }` tanpa schema `response[204]`. `t.Void`, `t.Undefined`, `t.Null`, `t.Object({})`, dan `t.Never` mengekspor bentuk yang ditolak.
- Parameter `path`, `query`, dan `header` hanya skalar. Header response seperti `Cache-Control` tidak dideklarasikan di OpenAPI sampai rule `response` diperluas.
- `operationId`, `tags` berisi satu tag, dan `security` dinyatakan pada `detail` setiap route.

**Key invariants**:
1. Komposisi Elysia tetap satu satunya sumber kontrak. Ekspor tidak membuka listener, koneksi PostgreSQL, migration, seed, atau request jaringan, dan `openapi.json` tidak pernah diedit manual. Bukti otomatisnya terbatas pada guard AC-1, guard tambahan untuk `Bun.redis`, `Bun.RedisClient`, `Bun.s3`, `Bun.S3Client`, dan `connect` pada `net.Socket.prototype`, serta listener sentinel pada `DATABASE_URL`, `REDIS_URL`, dan `SMTP_HOST`. Yang tidak dijaga: `Bun.fetch` (readonly di Bun 1.4.2), `Bun.file` dengan URL `s3://`, `Worker`, `Bun.spawn`, `node:child_process`, dan lookup DNS. Koneksi nyata dari jalur itu ke alamat sentinel tetap tertangkap listener, tetapi koneksi ke alamat lain tidak.
2. Checker murni: tidak menulis file, tidak membaca file selain input CLI, tidak mengakses jaringan, tidak menyelesaikan reference di luar dokumen, dan tidak mengubah dokumen yang diperiksa. Pattern regex hanya dikompilasi, tidak dijalankan.
3. Allow list berlaku di setiap level. Bentuk baru (misalnya nullable, union, schema rekursif, `oauth2`, parameter cookie atau array, parameter tingkat path item, response `default`, atau header response) memerlukan pembaruan tabel aturan, fixture, dan bukti generator SDK pada spec fitur yang membutuhkannya sebelum dipakai route.
4. Checker membaca key hanya sebagai own property (`Object.hasOwn`), dan registry yang dikunci string dokumen memakai `Map` atau `Set`; key seperti `__proto__` dan `constructor` diperlakukan sebagai key biasa dan tunduk pada allow list.
5. Urutan key memakai perbandingan code unit dan ditulis dari array key terurut. Urutan array tidak pernah diubah karena dapat bermakna.
6. Exporter memuat komposisi lewat `await import()` di dalam blok penanganan kegagalan, menulis hanya setelah checker lulus dan teks kanonik tidak melebihi 8.388.608 byte, serta menulis ke file sementara di direktori yang sama lalu rename, sehingga kegagalan di tengah tidak meninggalkan file terpotong. File sementara dihapus bila penulisan gagal. Setiap exception tidak terduga menjadi kegagalan generik dengan exit code 1. Sebelum menulis, exporter menunggu satu giliran timer agar rejection, exception immediate, atau timer tanpa jeda dari komposisi dilaporkan lebih dulu dan handler proses berhenti sebelum operasi file. Penulisan file sementara sampai rename berjalan sinkron, sehingga handler tidak pernah berjalan di tengahnya. Exception dari timer komposisi yang berjalan sesudah rename tetap membuat exit code 1, tetapi tidak dapat membatalkan file yang sudah diganti dari dokumen yang lulus checker.
7. Pesan kegagalan hanya memakai teks tetap dan rule ID. Isi dokumen, nilai field, path file, pesan parser, dan stack tidak pernah dicetak.
8. Waktu pemeriksaan linear terhadap ukuran dokumen. Setiap pohon schema ditelusuri sekali dengan batas kedalaman, target `$ref` tidak diekspansi di tempat, dan deteksi siklus memakai penandaan tiga warna dengan stack eksplisit sehingga setiap komponen diproses sekali dan rantai komponen panjang tidak memakai rekursi.
9. Tabel operasi wajib hanya bertambah melalui spec fitur pemilik route, bersama test yang membuktikan entri barunya.
10. Kelulusan checker hanya membuktikan subset proyek. Build Angular dan test request/response nyata tetap diperlukan sesuai aturan OpenAPI/SDK.

**Security model**: Ini tooling build lokal dan CI, bukan endpoint HTTP. Pelakunya pengembang atau job CI yang memeriksa file dari checkout, termasuk branch yang mungkin memuat kontrak berbahaya atau sangat besar. Batas baca 8 MiB, penolakan file non reguler, batas kedalaman, pemeriksaan linear, allow list, reference lokal saja, dan pesan tetap membatasi konsumsi resource serta mencegah isi file atau path bocor ke log CI. `sdk:generate` hanya berjalan setelah validasi lulus pada `api:sync`, sehingga batas yang sama melindungi generator. Rule `security` hanya memeriksa deklarasi; otorisasi runtime tetap dibuktikan oleh spec fitur pemilik route. Tidak ada autentikasi, akses database, data pribadi, atau credential.

**Configuration required**: Tidak ada variable environment, secret, atau layanan baru.

## Build plan

Urutan mengikuti Tracer Bullet: satu jalur tipis dari route nyata, exporter, checker, CLI, sampai `api:sync` dibuktikan dulu dengan satu rule, lalu aturan lain ditebalkan pada jalur yang sama.

1. Jalur tipis. Tambahkan `OPENAPI_RULE_IDS`, `OpenApiRuleId`, dan `OpenApiContractError` di checker, `scripts/lib/canonical-json.ts` sebagai serializer rekursif, CLI validator dengan satu argumen, pemeriksaan file biasa, batas baca 8 MiB, dan stderr dua baris, serta exporter yang memuat komposisi lewat `await import()`, menangkap semua kegagalan, membatasi ukuran teks kanonik, dan menulis lewat file sementara lalu rename. Terapkan rule `operation-id` dalam bentuk baru. Pindahkan `workspace()` dan `run()` ke `tests/integration/contract/workspace.ts`, tambahkan `no-network-preload.ts`, lalu buktikan `OPENAPI-001` serta kasus (a) sampai (e) `OPENAPI-005`. 2. Aturan dokumen dan operasi. Terapkan rule `document`, `version`, `info`, `path`, `method`, `operation`, `tag`, `parameter`, `request-body`, `response`, dan `required-operation` dengan `REQUIRED_OPERATIONS`, menurut urutan evaluasi tabel. Perbarui `valid.json` ke bentuk ekspor saat ini (response 200 memakai `$ref`) dan sesuaikan helper mutasi APP-003 di `tests/integration/contract/openapi.test.ts` tanpa menghapus skenario APP-003. ## Consequences

**Positive**:
- Bentuk yang tercantum di AC-7 terbukti dapat dibaca generator SDK, sehingga kesalahan seperti body yang hilang dari SDK, response bertipe `unknown`, parameter cookie yang terkirim sebagai query, parameter yang bentrok di `<Operasi>$Params`, response 2xx kedua yang diabaikan, atau operasi `trace` yang hilang tertangkap sebelum generate.
- Pengembang mendapat rule ID yang pasti untuk satu dokumen dan dapat dicari di tabel aturan tanpa membocorkan isi dokumen.
- Hasil ekspor tidak lagi bergantung pada locale mesin pengembang atau CI, dan kegagalan komposisi tidak lagi mencetak stack.
- Fitur 9 dan 10 mendapat batas kontrak tertulis, resep route yang diekspor bersih, dan satu tempat untuk menambah operasi wajib.

**Negative / tradeoffs**:
- Allow list ketat: setiap bentuk baru membutuhkan pembaruan checker, fixture, dan bukti SDK pada fitur yang membutuhkannya.
- `t.Integer`, `t.Numeric`, dan `t.Nullable` dari Elysia 1.4.30 belum dapat dipakai pada schema yang diekspor karena menghasilkan `anyOf` atau bentuk nullable campuran. Route memakai bentuk yang diekspor bersih, misalnya `Type.Integer` dari `@sinclair/typebox` yang sudah dipin atau `t.Number`.
- `t.Ref('Item')` di dalam model atau `t.Array(t.Ref('Item'))` diekspor Elysia 1.4.30 sebagai `$ref` nama telanjang, dan `t.Array` berisi schema ber `$id` diekspor dengan `$id` bersarang; keduanya ditolak. Untuk sementara model bersifat datar: model bernama hanya dirujuk dari root body atau response, dan daftar model bernama atau model bersarang belum tersedia sampai fitur yang membutuhkannya memutuskan cara ekspornya.
- Response 204 hanya dapat diekspor lewat `detail.responses` tanpa schema response, sehingga Elysia tidak memvalidasi body 204 (body itu memang kosong).
- Parameter array, parameter tingkat path item, dan response `default` ditolak walau sah menurut OpenAPI, karena belum ada route yang memakainya dan parameter array membutuhkan bukti serialisasi runtime.
- Setiap operasi wajib mendeklarasikan `security` sendiri, termasuk route publik yang menulis `security: []`. `security` dokumen tetap diperiksa tetapi tidak diwarisi, karena `security: []` di `apps/backend/src/app.ts` akan membuat route terlindungi yang lupa `detail.security` terekspor sebagai publik.
- Versi `3.0.3` yang dahulu diterima kini ditolak. Belum ada producer atau test yang memakainya, tetapi file eksperimen dengan versi lain tidak lagi lolos.
- Rule ID dan urutannya menjadi permukaan kecil yang dirujuk test dan dokumentasi, sehingga mengganti nama atau urutan rule perlu pembaruan spec.
- Batas 8 MiB dan 32 tingkat dapat perlu ditinjau bila kontrak tumbuh jauh.

**Neutral**:
- Route, perilaku runtime, database, dan konfigurasi tidak berubah. Serializer code unit mereproduksi `openapi.json` saat ini secara byte identik, sehingga SDK juga diharapkan identik; build plan langkah 1 membuktikannya.
- Generator tetap mengetik objek bersarang inline sebagai `Record<string, unknown>`, array bersarang secara longgar, `const` tanpa `enum` sebagai `string`, dan operasi 204 sebagai `unknown`. Ini batas generator, bukan pelanggaran checker; route yang butuh tipe tepat memakai model bernama atau `enum`, seperti route status.
- Elysia membuat `operationId` otomatis (misalnya `getApiStatus`) bila route tidak mendeklarasikannya, sehingga checker tidak dapat membedakan nama eksplisit dari nama otomatis. Tabel operasi wajib dan review route menjaga kewajiban `operationId` eksplisit dari aturan OpenAPI/SDK.
- Checker tidak memeriksa bentrok nama dengan identifier bawaan SDK, misalnya model bernama `ApiConfiguration`, `HttpClient`, atau `<Tag>Service`. Bentrok seperti itu gagal secara jelas saat build Angular yang wajib dijalankan sesudah `api:sync`.
- Tidak membutuhkan migration plan: perubahan berada dalam satu commit yang dapat dibatalkan dengan revert, tanpa data hidup.

## Follow-up

- [ ] Fitur 10 (spec 0006): saat fitur 10 dirancang atau dibangun, spec 0006 menambah rujukan ke spec ini beserta kewajibannya: entri `GET /api/readiness` dengan security `[]` masuk `REQUIRED_OPERATIONS` bersamaan dengan route fitur 10, response 200 memakai model bernama, `appliedMigrations` memakai `Type.Integer` dari `@sinclair/typebox` (bukan `t.Integer`), response 400, 429, dan 503 memakai schema yang lulus rule `schema`, dan header `Cache-Control` tidak dideklarasikan di OpenAPI sampai rule `response` diperluas lebih dahulu. Resep yang sama tertulis di `docs/rules/openapi-sdk.md` melalui build plan langkah 5.
- [ ] Fitur 9 tetap memiliki pemeriksaan drift dan manifest SDK di `scripts/check-api.ts` serta bukti request/response SDK terhadap backend nyata; spec ini tidak mengubahnya.
- [ ] Fitur 15 memakai `apiKey` dengan `in: cookie` bila memilih sesi cookie; `oauth2` atau `openIdConnect` memerlukan pembaruan rule `security` beserta bukti SDK. Elysia 1.4.30 mengekspor dan menerima body `application/x-www-form-urlencoded` serta `multipart/form-data` untuk route body object, termasuk dengan `type: 'json'` (probe: body form ke route seperti itu mendapat 200), sehingga perlindungan CSRF sesi cookie tidak boleh bergantung pada content type.
- [ ] Fitur pertama yang membutuhkan daftar model bernama atau model bersarang memutuskan cara ekspornya, misalnya exporter menulis ulang `$ref` nama telanjang menjadi pointer lokal bila nama ada di `components.schemas`, beserta rule dan bukti SDK.
- [ ] Fitur pertama yang membutuhkan parameter array membawa aturan lokasi (query saja), bukti serialisasi runtime satu dan dua elemen terhadap route Elysia nyata sesuai aturan testing, dan bukti SDK.
- [ ] Tinjau ulang batas 8 MiB dan 32 tingkat bila ukuran atau kedalaman kontrak terukur mendekatinya.
