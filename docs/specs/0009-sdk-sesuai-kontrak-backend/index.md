# 0009. SDK yang sesuai kontrak backend

**Date**: 2026-10-03
**Status**: Accepted

## Summary

`api:check` kini membuat ulang `openapi.json` dan SDK Angular di folder sementara, dua kali, lalu membandingkannya dengan file di checkout tanpa mengubah checkout. Setiap file yang akan bertambah, berubah, atau hilang disebut namanya, hasilnya tidak lagi bergantung pada locale mesin, dan proses yang macet atau dihentikan tidak meninggalkan proses maupun folder sementara. Aplikasi Angular memakai SDK hanya melalui konfigurasi aplikasi dan adapter fitur, dan sebuah test memanggil SDK hasil generate ke backend nyata untuk `GET /api/status`. Pola adapter dan harness test ini menjadi pegangan fitur 10 ketika membangun adapter pertama.

## Requirements

**User stories**:
- Sebagai pengembang, saya ingin `api:check` menyebut file OpenAPI atau SDK yang tertinggal tanpa mengubah checkout, agar saya tahu file mana yang akan diubah `api:sync` dan file tanpa pemilik mana yang harus saya hapus sendiri.
- Sebagai pengembang frontend, saya ingin batas impor SDK yang ditegakkan checker, kontrak adapter tertulis, dan harness backend nyata, agar adapter pertama di fitur 10 memanggil operasi SDK melalui proxy `/api` tanpa endpoint atau DTO HTTP tulisan tangan.
- Sebagai pemilik proyek, saya ingin bukti bahwa request dan response SDK cocok dengan backend nyata, agar build yang lulus tidak disalahartikan sebagai kontrak yang bekerja.

**Acceptance criteria**:
- **AC-1**: `bun run api:sync` menjalankan `api:openapi`, `api:validate`, lalu `sdk:generate` berurutan dan berhenti dengan exit code bukan nol pada tahap pertama yang gagal tanpa menjalankan tahap sesudahnya. Script `sdk:generate` menjalankan generator dari working directory `apps/frontend/` dengan `LC_ALL=en_US.UTF-8`. Pada workspace terisolasi yang hanya berisi input `API_INPUTS` dan symlink `node_modules`, satu `api:sync` menghasilkan `openapi.json` dan isi `apps/frontend/sdk/` yang byte identik dengan artefak tersimpan, dan tidak ada path lain di workspace yang dibuat, diubah, atau dihapus. Di seluruh spec ini, folder byte identik berarti `diffArtifacts` tidak menemukan perbedaan: himpunan path entry dan jenisnya sama dan setiap file berisi byte yang sama, sedangkan direktori kosong diabaikan.
- **AC-2**: `apps/frontend/sdk.config.json` berisi tepat satu target dengan `input` `../../openapi.json`, `output` `./sdk`, `mode` `standalone`, `clientName` `FoundationApi`, `rootUrl` `""`, `splitByDomain` `false`, fitur `models`, `operations`, `services`, dan `client` bernilai `true`, serta `metadata`, `navigation`, dan `resources` bernilai `false`. `tsconfig.app.json` memasukkan `sdk/**/*.ts`, dan `tsconfig.json` memetakan `@sdk` ke `./sdk/public-api.ts`. `apps/frontend/src/app/app.config.ts` memasang `provideHttpClient()` dari `@angular/common/http` dan `provideApiConfiguration('')` dari `@sdk`. `bun run build:frontend` lulus, dan JavaScript hasil build production memuat teks `rootUrl` dari konfigurasi SDK. Di workspace terisolasi, baris `export const sdkBuildProbe: number = 'x';` yang ditambahkan ke `sdk/models/development-status.ts`, file yang tidak diimpor aplikasi, membuat `ng build` berakhir dengan exit code bukan nol dan error TypeScript pada file itu.
- **AC-3**: `bun run check:frontend:bundle` memeriksa setiap file `.ts` dan `.tsx` di bawah `apps/frontend/src`, kecuali `*.spec.ts`, `*.spec.tsx`, `*.test.ts`, dan `*.test.tsx`, dalam urutan code unit path relatif, dan menerapkan tabel *Bentuk impor SDK*. Specifier `@sdk` hanya diterima pada `apps/frontend/src/app/app.config.ts` dan adapter `apps/frontend/src/app/features/<fitur>/<fitur>-api.ts`, dengan dua nama `<fitur>` yang sama dan cocok dengan `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`, dan hanya dalam bentuk yang diterima tabel. Specifier `@sdk/...` di file mana pun dan specifier relatif yang, dihitung dengan `resolve(dirname(file), specifier)`, sama dengan atau berada di dalam `resolve(applicationSource, '../sdk')` ditolak. Pada pelanggaran pertama (file pertama menurut urutan, lalu specifier pertama menurut urutan sumber), `scripts/check-frontend-bundle.ts` menulis ke stderr tepat `Browser application imports the SDK outside a feature adapter from <path>.` dan satu newline, stdout kosong, dan exit code 1, dengan `<path>` relatif terhadap working directory memakai `/`; path yang tidak cocok `^[A-Za-z0-9._@+/-]+$` ditulis sebagai literal berkutip ganda dengan escape `\uXXXX`, sama dengan baris laporan `api:check`, sehingga pesan tetap satu baris. Checker tidak mengikuti symlink: symlink pertama menurut urutan code unit path di bawah `apps/frontend/src`, sebelum aturan impor diperiksa, atau di bawah `apps/frontend/dist`, sebelum aset dipindai, membuat checker menulis tepat `Frontend bundle check does not follow the symlink <path>.` dengan bentuk yang sama. Pesan tetap checker yang lain (modul khusus server, credential, build belum ada) keluar dengan bentuk yang sama, dan error lain menulis tepat `Frontend bundle check failed.` dan satu newline; stack, potongan source, dan versi runtime tidak pernah dicetak. Seluruh kasus UI-003 yang ada tetap lulus.
- **AC-4**: Saat `bun run test:frontend`, tepat satu backend nyata dimulai untuk seluruh run Vitest dengan `bun --no-env-file apps/backend/src/index.ts` dari root, environment yang hanya berisi `PATH`, `HOME`, `NODE_ENV=development`, `HOST=127.0.0.1`, dan `PORT` berupa port loopback kosong pilihan sistem operasi, tanpa `DATABASE_URL`. Setiap pemanggilan `globalSetup` memberikan `sdkContractBackendUrl` dan `sdkContractClosedUrl` (URL port loopback yang dibuka lalu ditutup harness) lewat `project.provide`. Dengan provider `appConfig` dan `provideHttpClientTesting()`, `ApiConfiguration.rootUrl` bernilai `''` dan `DevelopmentService.getDevelopmentStatus()` mengirim tepat satu request `GET` ke URL relatif `/api/status` dengan header `Accept: application/json`, tanpa body, tanpa header `Authorization`, dan tanpa `withCredentials`. Dengan provider `appConfig` ditambah `provideApiConfiguration(sdkContractBackendUrl)`, `DevelopmentService.getDevelopmentStatus$Response()` dan `FoundationApi.invoke$Response(getDevelopmentStatus, {})` melalui `HttpClient` nyata ke backend nyata menghasilkan status 200, `url` `<sdkContractBackendUrl>/api/status`, `Content-Type` yang diawali `application/json`, dan body yang sama persis dengan `{ "status": "ok" }` serta diterima tipe `DevelopmentStatus`. Operasi SDK dengan `rootUrl` `<sdkContractBackendUrl>/missing` gagal sebagai `HttpErrorResponse` berstatus 404 dengan body `{ "error": "Not found" }`, dan operasi dengan `rootUrl` `sdkContractClosedUrl` gagal sebagai `HttpErrorResponse` berstatus 0. Run itu mencetak tepat satu baris `SDK contract backend listening on 127.0.0.1:<port>`, mencetak `SDK contract backend stopped` sesudah semua test, lalu port tersebut menolak koneksi. Run yang sama tetap lulus ketika environment induk memuat `DATABASE_URL=not-a-url` dan `FOUNDATION_TEST_SECRET` sentinel serta root workspace memuat `.env` berisi `DATABASE_URL=not-a-url`; backend yang menerima nilai itu gagal start, sehingga kelulusan membuktikan kedua nilai tidak sampai ke backend. `sdkContractBackendEnvironment(parent, port)` menghasilkan objek dengan tepat lima kunci di atas, dan `startSdkContractBackend` dengan perintah yang tidak ada atau perintah yang keluar sebelum siap gagal dengan `SDK contract backend did not start` sesudah tiga percobaan tanpa proses sisa.
- **AC-5**: Di workspace terisolasi, route uji pada tag baru yang ditambahkan ke komposisi development, dengan model bernama `ProbeAvailable` untuk status 200 dan `ProbeUnavailable` untuk status 503, lulus `api:validate`, lalu `api:sync` membuat file kedua model, operasi, dan service tag itu, `public-api.ts` mengekspor tipe `ProbeAvailable` dan `ProbeUnavailable`, dan manifest `apps/frontend/sdk/.ojiepermana-sdk-manifest.json` berversi `1` mencantumkan setiap file hasil generate, kecuali manifest itu sendiri, dalam urutan terurut. Setelah route dihapus dan `api:sync` dijalankan lagi, file tersebut terhapus dan `apps/frontend/sdk/` kembali byte identik dengan artefak tersimpan; direktori kosong yang ditinggalkan generator diabaikan. File di `apps/frontend/sdk/` yang tidak tercantum di manifest tidak dihapus generator, dan `api:check` melaporkannya sebagai `removed`. File yang tidak tercantum di manifest pada path yang akan ditulis generator, dengan isi berbeda, membuat `sdk:generate` berakhir dengan exit code bukan nol dan seluruh isi `apps/frontend/sdk/` tetap byte identik.
- **AC-6**: `bun run api:check` menjalankan `bun --no-env-file scripts/check-api.ts`, yang memanggil `runApiCheck` dengan batas 120.000 ms per `api:sync`. `runApiCheck` membuat direktori `mkdtemp` di bawah direktori temp sistem, menyalin `API_INPUTS` ke subdirektori `workspace/` tanpa file bernama `.env` atau `.env.*` di level mana pun, menautkan `node_modules`, tanpa `openapi.json` maupun `apps/frontend/sdk/`, lalu menjalankan `bun --no-env-file run api:sync` di sana dua kali dengan environment yang hanya berisi `PATH` dan `HOME` (urutan pembandingan pada AC-7). Bila kedua run sama, `openapi.json` dan setiap entry di bawah `apps/frontend/sdk/` pada checkout, termasuk manifest dan file di luar manifest, dibandingkan byte demi byte dengan hasil regenerasi. Setiap perbedaan dicetak ke stderr sebagai satu baris `added <path>` (dibuat regenerasi, tidak ada di checkout), `changed <path>` (ada di kedua sisi dengan jenis entry atau isi berbeda), atau `removed <path>` (ada di checkout, tidak dibuat regenerasi), dengan path relatif root. Baris dikelompokkan berurutan `added`, `changed`, lalu `removed`; setiap kelompok berurutan code unit dan paling banyak 200 baris, disusul satu baris `... and <n> more <jenis>` bila lebih. Sesudah baris itu dicetak `OpenAPI or SDK drift detected` dan exit code 1. Satu run yang memuat sekaligus file SDK yang diubah, file SDK yang dihapus, file tanpa pemilik, entri manifest usang beserta filenya, symlink di `apps/frontend/sdk/`, dan `openapi.json` yang hilang menghasilkan tepat baris yang diharapkan untuk setiap kasus; symlink dilaporkan `removed` tanpa diikuti. Perubahan route status di backend tanpa `api:sync` menghasilkan `changed openapi.json` serta baris `changed` untuk file SDK yang terdampak. Pada hasil lulus maupun gagal, daftar file dan isi checkout tetap byte identik, direktori sementara terhapus dari `TMPDIR`, dan output tidak memuat isi file.
- **AC-7**: `api:check` selalu menjalankan `api:sync` dua kali berurutan di workspace sementara yang sama. Sebelum run kedua, `openapi.json` dan `apps/frontend/sdk/` hasil run pertama disalin ke subdirektori `run1/` di direktori sementara yang sama. Run pertama dibandingkan dengan run kedua lebih dulu. Bila berbeda, baris dicetak dengan format AC-6 dari sudut pandang run pertama ke run kedua (`added` berarti ada di run kedua dan tidak di run pertama), diikuti `OpenAPI or SDK generation is not repeatable` dan exit code 1, tanpa membandingkan dengan checkout. Contohnya, `sdk:generate` workspace yang diganti generator yang menambahkan waktu saat ini ke `apps/frontend/sdk/api.ts` menghasilkan tepat satu baris `changed apps/frontend/sdk/api.ts` lalu pesan itu. Bila kedua run sama, pembandingan checkout AC-6 berlaku, dan bila checkout juga sama, stdout memuat `OpenAPI and SDK match stored artifacts across two runs` dan exit code 0. Dengan fixture kontrak yang menambah operasi `getChart` dan `getHelp` pada tag `development`, `bun run sdk:generate` dari proses dengan `LC_ALL` dan `LANG` bernilai `cs_CZ.UTF-8` maupun `en_US.UTF-8` menghasilkan isi `apps/frontend/sdk/` yang byte identik, dan `public-api.ts` mengekspor ketiga operasi dengan urutan `getChart`, `getDevelopmentStatus`, `getHelp`.
- **AC-8**: `api:check` tidak memakai cache, git, atau deteksi perubahan untuk melewati tahap. Pada workspace dengan perubahan backend yang tidak mengubah kontrak, yaitu komentar baru dan handler status yang mengembalikan nilai sama melalui ekspresi berbeda, `api:check` berakhir dengan exit code 0, dan outputnya memuat `OpenAPI exported without listener`, `OpenAPI project checks passed`, dan `[sdk] standalone → sdk` masing masing tepat dua kali. Workflow `.github/workflows/application.yml` menjalankan job pada setiap `push` dan `pull_request` tanpa `paths` atau `paths-ignore`, dan script `test:ci` menjalankan `api:check` sebelum `build:frontend`, `test:frontend`, `test:integration`, dan `test:e2e`.
- **AC-9**: Di workspace terisolasi dengan file `.env` berisi nilai sentinel pada root, `apps/backend/`, dan `apps/frontend/`, serta proses `bun run api:sync` yang environment-nya memuat `DATABASE_URL` sentinel berpassword palsu dan satu variable `FOUNDATION_TEST_SECRET` sentinel, `api:sync` lulus, dan `openapi.json` serta setiap file `apps/frontend/sdk/` tidak memuat nilai sentinel, path absolut workspace, `localhost`, maupun `127.0.0.1`. `copyApiInputs` tidak menyalin `.env` maupun `.env.*` di level mana pun, menyalin symlink apa adanya tanpa menulis ulang targetnya, dan gagal ketika sebuah symlink di dalam input, termasuk input teratas, memiliki target absolut atau target relatif yang tidak kanonik (lihat `API_INPUTS`), misalnya `../../../outside.txt` yang keluar dari root checkout, `../node_modules/../.env`, `../node_modules`, atau `up/../..` di samping `up -> ..`, serta ketika segmen induk sebuah input, misalnya `apps` pada `apps/backend`, bukan direktori nyata; pada `api:check` kegagalan itu menjadi `API check failed` dan exit code 1. Setiap file `.ts` di `apps/frontend/sdk/` diawali baris `/* eslint-disable */` dan `/* Auto-generated by @ojiepermana/angular/sdk. DO NOT EDIT. */`. `docs/rules/openapi-sdk.md` merujuk spec ini serta menjelaskan pemilik tunggal artefak, cara kerja `api:check` termasuk arti baris `removed` dan penghapusan manual file tanpa pemilik, pin locale, batas impor SDK, kontrak adapter, dan harness backend nyata. Tidak ada dependency, variable environment aplikasi, secret, route, atau perubahan database baru.
- **AC-10**: `api:check` menjalankan setiap `api:sync` dalam process group sendiri. Bila satu `api:sync` melewati batas waktu (120.000 ms pada CLI, nilai kecil lewat parameter `syncTimeoutMs` pada test), atau `api:check` menerima SIGINT atau SIGTERM, seluruh group menerima SIGTERM, lalu SIGKILL bila group masih hidup sesudah 5 detik, dan `api:check` menunggu group habis sebelum menghapus direktori sementara. Batas waktu menghasilkan `API synchronization failed` dan exit code 1; SIGINT dan SIGTERM menghasilkan exit code 130 dan 143 tanpa baris laporan. Pada ketiga jalur, proses cucu yang dimulai tahap tersebut sudah mati, direktori sementara milik run itu tidak tersisa di `TMPDIR`, dan checkout tetap byte identik.

## Decision

**Chosen option**: Perkuat tooling yang ada. `api:check` meregenerasi di workspace terisolasi dari keadaan kosong dua kali dan membandingkan pohon file secara utuh, `sdk:generate` mempin locale, SDK hanya diimpor oleh `app.config.ts` dan adapter fitur, dan kesesuaian SDK dibuktikan oleh Vitest melalui Angular CLI terhadap backend nyata. (basis: `docs/rules/openapi-sdk.md` bagian sinkronisasi dan konfigurasi SDK, spec 0008, scope fitur 9)

Generator, mode `standalone`, lokasi `apps/frontend/sdk/`, alias `@sdk`, dan urutan `api:sync` tetap. Fitur ini tidak membuat adapter tanpa pemakai; adapter pertama dibangun fitur 10 menurut *Kontrak adapter fitur* di bawah. Pemilik tunggal artefak bersama adalah agent utama selama pekerjaan paralel, atau pengembang yang mengintegrasikan perubahan bila bekerja sendiri.

**Implementation skills**: `angular-developer` (skill pengguna, `~/.claude/skills/angular-developer/`), terutama `references/creating-services.md` dan `references/http-client.md` untuk `@Service()`, backend `fetch` bawaan, dan `HttpErrorResponse`.

**`API_INPUTS`** (urutan tetap; setiap path disalin bila ada): `package.json`, `scripts/`, `apps/backend/`, `libs/`, `apps/frontend/angular.json`, `apps/frontend/sdk.config.json`, `apps/frontend/.prettierrc`, `apps/frontend/.editorconfig`. Penyalinan memakai `cp` dengan `recursive: true` dan `verbatimSymlinks: true`, sehingga symlink disalin dengan target yang sama persis. Nama `.env` dan `.env.*`, `node_modules`, `dist`, dan `.angular` dilewati. Sebelum menyalin, setiap segmen induk path input, misalnya `apps` pada `apps/backend`, diperiksa dengan `lstat` dan harus direktori nyata, dan setiap symlink di dalam input, termasuk input teratas, diperiksa tanpa diikuti. Target yang diterima hanya target relatif kanonik: segmen `..` hanya sebagai urutan di awal, direktori yang dicapai urutan itu dari `dirname(link)` tetap di dalam root checkout, lalu nama biasa tanpa `..` dan tanpa `node_modules`. Target absolut atau target lain membuat `copyApiInputs` melempar error. Dengan bentuk itu hasil leksikal sama dengan tujuan fisik di workspace: `..` di awal hanya menaiki direktori nyata yang sudah diperiksa, setiap symlink yang dilewati nama biasa diperiksa dengan aturan yang sama, dan satu satunya symlink lain di workspace, `node_modules`, tidak pernah dilewati. Karena itu symlink yang diterima hanya dapat menjangkau salinan di workspace, yang tidak pernah memuat `.env`. (Pemeriksaan leksikal saja menerima `../node_modules/../.env`, yang di workspace sampai ke `.env` checkout lewat symlink `node_modules`, dan `up/../..` di samping `up -> ..`, yang naik dua tingkat di atas workspace; review 2026-10-03.) **`API_OUTPUTS`**: `openapi.json` dan `apps/frontend/sdk/`. Input yang kurang membuat regenerasi gagal, bukan lulus diam diam; route yang kelak mengimpor path di luar daftar ini menambahkan path tersebut di `API_INPUTS` bersama spec fiturnya.

**Bentuk impor SDK** (ditegakkan `check:frontend:bundle`, AC-3; "adapter" berarti `src/app/features/<fitur>/<fitur>-api.ts`):

| Bentuk di file yang diperiksa | Adapter | `src/app/app.config.ts` | File lain di `apps/frontend/src` |
|---|---|---|---|
| `import { A, type B } from '@sdk'` | Diterima | Diterima | Ditolak |
| `import type { A } from '@sdk'` | Diterima | Diterima | Ditolak |
| `export type { A } from '@sdk'` | Diterima | Ditolak | Ditolak |
| `import '@sdk'`, `import * as ns from '@sdk'`, import default dari `@sdk` | Ditolak | Ditolak | Ditolak |
| `export { A } from '@sdk'`, `export { type A } from '@sdk'`, `export * from '@sdk'`, `export * as ns from '@sdk'`, `export type * from '@sdk'`, `export type * as ns from '@sdk'` | Ditolak | Ditolak | Ditolak |
| `import('@sdk')`, tipe `import('@sdk')`, `require('@sdk')`, `import x = require('@sdk')` | Ditolak | Ditolak | Ditolak |
| Ekspor lokal binding yang diimpor dari `@sdk`: `export { A }`, `export { A as B }`, `export type { A }`, `export default A`, `export = A` | Ditolak | Ditolak | Tidak berlaku |

Checker hanya membaca deklarasi impor dan ekspor. Nilai SDK yang keluar lewat konstanta (`export const X = DevelopmentService`) atau nilai kembali method tidak tertangkap; kontrak adapter butir 2 dan 3 melarangnya, dan review fitur pemilik memeriksanya.

**Kontrak adapter fitur** (pola untuk fitur 10 dan seterusnya; batas impor ditegakkan AC-3, butir 6 dibuktikan AC-5, sisanya diperiksa `/check verify` dan review fitur pemilik):
1. Satu adapter per area fitur pada `apps/frontend/src/app/features/<fitur>/<fitur>-api.ts`, berupa class `<Fitur>Api` dengan `@Service()` dari `@angular/core`.
2. Adapter memanggil operasi SDK melalui service tag hasil generate, misalnya `inject(DevelopmentService)`. Adapter tidak memakai `HttpClient`, string URL, atau `RequestBuilder` secara langsung, tidak mengubah `rootUrl`, dan tidak mengeluarkan nilai SDK (service, fungsi operasi, atau `FoundationApi`) kepada pemanggil.
3. Method adapter mengembalikan `Observable` dingin dari operasi SDK. Adapter tidak subscribe dan tidak menyimpan state; state dimiliki component atau store fitur.
4. Tipe sukses memakai model SDK yang diekspor ulang dengan `export type { ... } from '@sdk'`, atau model tampilan milik fitur. Interface yang menyalin model SDK tidak dibuat.
5. Adapter memetakan `HttpErrorResponse` ke tipe hasil atau error milik fitur. Status 0 berarti kegagalan jaringan. Status yang dideklarasikan backend dengan body bermodel bernama memakai tipe SDK hasil generate, yang dipersempit dengan memeriksa field pembeda (misalnya `status`) sebelum dipakai. Status lain menjadi kegagalan umum. Component tidak menerima `HttpErrorResponse` atau body error mentah, dan teks untuk pengguna berasal dari fitur.
6. Body error yang dibutuhkan UI dideklarasikan backend sebagai model bernama (`.model({ Nama: schema })` lalu dirujuk dengan nama pada status itu), sehingga generator mengeluarkan tipenya. AC-5 membuktikan model bernama pada status 503 lulus checker dan menghasilkan model SDK beserta ekspor tipenya.
7. Test adapter memakai `sdkContractBackendUrl` untuk hasil yang dapat dihasilkan backend tanpa database, `sdkContractClosedUrl` untuk kegagalan jaringan, `HttpTestingController` untuk bentuk request, dan Playwright untuk alur browser melalui proxy `/api`.

**Key invariants**:
1. `api:check` hanya membaca checkout. Semua penulisan terjadi di direktori sementara, yang dihapus saat selesai, saat gagal, saat batas waktu, dan saat SIGINT atau SIGTERM, selalu sesudah seluruh process group tahap habis (exit 130 atau 143 untuk sinyal).
2. Kesamaan artefak berarti kesamaan byte seluruh pohon file. Tidak ada normalisasi newline, whitespace, atau urutan, dan tidak ada daftar abaikan; file lokal seperti `.DS_Store` ikut dilaporkan.
3. Regenerasi selalu dimulai tanpa `openapi.json` dan tanpa `apps/frontend/sdk/`, sehingga hasil hanya bergantung pada `API_INPUTS`, versi tool yang dipin, dan locale yang dipin. File tanpa pemilik, entri manifest usang, dan manifest rusak muncul sebagai perbedaan pohon tanpa aturan khusus.
4. Tidak ada cache, git, atau deteksi perubahan. Setiap `api:check` menjalankan ekspor, validasi, dan generate dua kali, termasuk ketika hasilnya identik, dan pengulangan diperiksa sebelum drift.
5. Artefak bersama (`openapi.json`, `apps/frontend/sdk.config.json`, `apps/frontend/sdk/`) hanya ditulis oleh `api:sync` yang dijalankan pemilik tunggal. Selama pekerjaan paralel, subagent tidak menjalankan `api:sync` pada checkout bersama; mereka menyerahkan perubahan route, lalu agent utama menjalankan `api:sync` sekali sesudah integrasi dan memberi tahu subagent frontend bahwa SDK siap. `api:check` di CI menangkap sisa yang terlewat.
6. File hasil generate di `apps/frontend/sdk/` tidak pernah diedit manual dan tidak pernah dihapus paksa untuk menutupi konflik. Perbaikan berada di schema backend, konfigurasi generator, atau adapter fitur. File yang tidak dibuat generator (baris `removed`, atau file tanpa pemilik yang menghalangi `sdk:generate`) dihapus manual oleh pemilik artefak; itu perbaikan sah karena file tersebut bukan hasil generate.
7. `@sdk` hanya diimpor `app.config.ts` dan adapter fitur dalam bentuk tabel *Bentuk impor SDK*. Component dan store memakai adapter.
8. Harness backend memakai satu proses per run, tanpa `.env`, tanpa `DATABASE_URL`, dan dengan stdio dibuang, hanya mendengar pada loopback, dan dihentikan oleh teardown pemakai terakhir, oleh setup yang gagal sebelum error dilempar, atau oleh `process.once('exit')`.
9. Output `api:check`, checker bundle, dan harness hanya memuat teks tetap, path artefak atau file sumber, dan port loopback. Isi file, environment, dan stack tidak dicetak; output tahap yang diteruskan dari child sudah dibatasi spec 0008.
10. Kelulusan `api:check`, build, dan test kesesuaian membuktikan operasi yang diuji saja. Operasi baru membawa test kesesuaiannya sendiri pada spec fitur pemilik route.

**Security model**: Fitur ini berupa tooling build, konfigurasi frontend, dan harness test, tanpa endpoint, data pribadi, autentikasi, atau akses database baru. Pelakunya pengembang atau job CI yang memproses checkout, termasuk branch yang mungkin memuat file besar, symlink, FIFO, nama file berkarakter kontrol, atau `.env` lokal. Kontrolnya: `api:check` hanya menyalin daftar input tetap tanpa `.env`, menyalin symlink apa adanya dan hanya menerima target relatif kanonik yang tetap di dalam root tanpa melewati `node_modules`, dengan segmen induk setiap input berupa direktori nyata, berjalan dengan `--no-env-file` dan environment `PATH` serta `HOME`, membuat direktori `mkdtemp` (mode 0700) yang selalu dihapus sesudah process group tahap habis, membaca checkout dengan `lstat` tanpa mengikuti symlink termasuk pada akar folder SDK, tidak membuka file tanpa pasangan atau berbeda ukuran, membandingkan lewat hash streaming, membatasi waktu tiap run, meng-escape nama file yang tidak biasa, dan tidak mencetak isi file. Checker bundle mencetak hanya pesan tetap tanpa stack atau path absolut, dengan path yang di escape seperti laporan `api:check`, dan menolak symlink yang tidak diikutinya karena build Angular mengikutinya. Harness backend tidak menerima credential dari induk maupun `.env` (dibuktikan dengan kontrol negatif `DATABASE_URL=not-a-url`), membuang output child, dan hanya mendengar pada `127.0.0.1`. `provideHttpClient()` memasang interceptor XSRF bawaan Angular untuk request mutasi same origin; kebijakan CSRF dan sesi tetap milik fitur 15. SDK generated bukan validasi keamanan server (aturan keamanan); `security: []` pada `GET /api/status` sesuai route development publik dari spec 0001.

## Build plan

Urutan mengikuti Tracer Bullet pada scope: satu jalur tipis dari SDK hasil generate, konfigurasi aplikasi, sampai backend nyata dibuktikan lebih dulu, lalu gerbang drift ditebalkan di atas jalur yang sama.

1. Jalur tipis konsumsi. Tambahkan `provideHttpClient()` dan `provideApiConfiguration('')` di `app.config.ts`. Ubah `scripts/lib/frontend-bundle.ts` dari larangan `@sdk` menyeluruh menjadi tabel *Bentuk impor SDK* dengan akar `apps/frontend/src`, urutan file code unit, dan `FrontendBundleError`; ubah `scripts/check-frontend-bundle.ts` agar menangkap error dan mencetak hanya pesan tetap; tambahkan kasus `SDK-003`. Tambahkan `vitest-base.config.ts`, `vitest-backend.setup.ts` (setup bertipe `TestProject`, state bersama berupa promise, `project.provide` pada setiap pemanggilan, `startSdkContractBackend`, `sdkContractBackendEnvironment`), `vitest-provided-context.d.ts` beserta `include` di `tsconfig.spec.json`, `runnerConfig` di `angular.json`, dan `sdk-contract.integration.spec.ts`, lalu bagian Vitest dan unit test harness `SDK-004`. Tambahkan file checker dan file Vitest ke `tsconfig.contract.json`. Jalankan `test:frontend`, `typecheck:contract`, `build:frontend` (catat ukuran initial bundle sebelum dan sesudah perubahan), `check:frontend:bundle`, dan `test:e2e` untuk memastikan APP-002 tetap tanpa request `/api` saat halaman dibuka. Satisfies **AC-2**, **AC-3**, **AC-4**.
2. Gerbang drift. Buat `scripts/lib/process-group.ts`, `scripts/lib/api-artifacts.ts`, dan `scripts/lib/api-check.ts`; jadikan `scripts/check-api.ts` CLI tipis dengan konstanta 120.000 ms; ubah script `api:check` menjadi `bun --no-env-file scripts/check-api.ts`. Ubah helper `tests/integration/contract/workspace.ts` ke tanda tangan pada *Lingkungan test* dengan `copyApiInputs` dan `runProcessGroup`, dan tambahkan file baru ke `tsconfig.contract.json`. Pastikan APP-003 tetap lulus tanpa mengubah asersinya, kecuali timeout eksplisit. Tambahkan `SDK-006`, bagian pengulangan `SDK-007`, `SDK-010`, dan bagian workspace `SDK-004`. Satisfies **AC-4**, **AC-6**, **AC-7**, **AC-10**.
3. Generator yang dapat diulang. Tambahkan `LC_ALL=en_US.UTF-8` pada `sdk:generate`, fixture locale, kasus manifest dan konflik termasuk `ProbeUnavailable` pada 503, cakupan tulis `api:sync`, serta bukti build `SDK-002`. Jalankan fixture locale `SDK-007` sekali di kontainer Linux Docker dengan Node 24.21.0 dan Bun 1.4.2, dependency dipasang di dalam kontainer dari `bun.lock` dengan `--frozen-lockfile` dan repo disalin, bukan `node_modules` macOS yang di-mount; bila kontainer tidak dapat dijalankan, catat `not_run` beserta alasannya di laporan bukti dan jangan nyatakan bagian Linux AC-7 terbukti. Jalankan `api:sync` di checkout dan pastikan artefak tersimpan tidak berubah. Satisfies **AC-1**, **AC-2**, **AC-5**, **AC-7**.
4. Regenerasi, secret, aturan, dan bukti. Tambahkan `SDK-008` dan `SDK-009`. Perbarui `docs/rules/openapi-sdk.md` (cara kerja `api:check`, arti baris `added`, `changed`, dan `removed` serta penghapusan manual file tanpa pemilik termasuk `.DS_Store`, pin locale, pemilik tunggal, batas impor dan tabel bentuknya, kontrak adapter, harness backend nyata, rujukan spec ini) dan satu kalimat rujukan pada bagian SDK `docs/rules/angular.md`. Tambahkan registry `tests/scenarios/sdk-contract.json` untuk `SDK-001` sampai `SDK-010`. Jalankan `api:sync`, `api:check`, `test:scenarios`, `typecheck:contract`, `test:frontend`, `test:integration`, `check:dependencies`, `build:frontend`, `check:frontend:bundle`, `test:e2e`, dan `test:ci`, serta `mkdir -p .local/feature-9 && bun test ./tests/integration/contract/sdk.test.ts --reporter=junit --reporter-outfile=.local/feature-9/sdk.xml`. Catat perintah, versi tool, ukuran bundle, hasil kontainer Linux, dan hasilnya di `docs/testing/0008-sdk-contract.md`, dan salin JUnit ke `docs/testing/evidence/0008/` tanpa atribut `hostname`, mengikuti laporan 0002 sampai 0007; bila nomor itu sudah terpakai saat build, gunakan nomor kosong berikutnya. Satisfies **AC-1** sampai **AC-10**.

## Consequences

**Positive**:
- `api:check` tidak lagi menimpa checkout dan menyebut file yang tertinggal, sehingga pengembang tahu persis apa yang akan diubah `api:sync` dan file mana yang harus dihapus sendiri.
- File tanpa pemilik, entri manifest usang, dan manifest rusak tertangkap oleh satu aturan: pohon file harus sama dengan hasil regenerasi dari kosong.
- SDK tidak lagi berubah karena locale pengembang, sehingga CI dan mesin lokal menghasilkan byte yang sama.
- Tahap yang macet atau dihentikan tidak meninggalkan proses generator maupun folder sementara, karena seluruh process group dihentikan sebelum pembersihan.
- Fitur 10 mendapat konfigurasi aplikasi, batas impor yang ditegakkan, kontrak adapter, dan harness backend nyata yang siap dipakai.

**Negative / tradeoffs**:
- `test:frontend` kini selalu memulai satu proses backend Bun, sehingga run frontend membutuhkan `bun` di `PATH` dan ikut gagal bila backend tidak dapat dimulai.
- `api:check` lebih lambat sedikit karena menyalin input, memulai dari kosong, dan menyalin hasil run pertama, dan suite SDK menambah kira kira satu sampai dua menit pada `test:integration` (perkiraan dari probe; dicatat saat build).
- `API_INPUTS` adalah daftar yang dirawat. Route yang kelak mengimpor path di luar daftar membuat `api:check` gagal sampai path itu ditambahkan, dan symlink input yang menunjuk ke luar root membuat `api:check` gagal.
- Penghentian group memakai `ps` melalui `groupAlive`, yang tersedia di macOS dan runner Linux CI; `api:check` bergantung pada perintah itu.
- Pembandingan memakai filesystem, bukan git, dan tidak punya daftar abaikan. File lokal yang diabaikan git di folder SDK, misalnya `.DS_Store` dari Finder macOS, membuat `api:check` lokal gagal dengan baris `removed` walau CI lulus; pengembang menghapusnya manual.
- Pin `LC_ALL=en_US.UTF-8` baru dibuktikan di macOS saat spec ini ditulis; langkah 3 menjalankan fixture locale di kontainer Linux sebelum AC-7 dinyatakan terbukti, dan CI mengulanginya lewat `SDK-007`.
- Spec 0007 AC-5 (halaman root tidak mengimpor SDK, dibuktikan UI-002, UI-003, dan `check:frontend:bundle`) kini berlaku untuk halaman dan component; `app.config.ts` dikecualikan oleh spec ini karena memasang konfigurasi SDK.
- Bundle awal bertambah karena `HttpClient` dan barrel `@sdk` kini dimuat oleh `app.config.ts`, sehingga seluruh SDK, termasuk `RequestBuilder`, masuk chunk awal dan bertambah sebanding dengan ukuran SDK. Pemeriksa silang mengukur initial total naik dari 654,09 kB ke 675,94 kB pada build production; angka itu belum diulang agent dan dicatat ulang saat build. Anggaran error 1 MB tetap berlaku, dan peringatan anggaran 500 kB yang sudah ada tetap tercatat.
- Checker hanya membaca deklarasi impor dan ekspor; nilai SDK yang keluar lewat konstanta atau nilai kembali method bergantung pada review.
- Harness bergantung pada perilaku Angular 22.2 yang memanggil `globalSetup` dua kali; pembaruan Angular dapat mengubahnya, dan baris `listening` tunggal di `SDK-004` akan menunjukkannya.

**Neutral**:
- Route, kontrak, `openapi.json`, dan isi SDK tidak berubah. `api:sync` pada checkout diharapkan identik dan tetap dilaporkan sebagai regenerasi berhasil.
- Tidak ada adapter pada fitur ini; component dan halaman pertama yang memakai SDK berasal dari fitur 10.
- Tidak membutuhkan migration plan: perubahan berada dalam satu commit yang dapat dibatalkan dengan revert, tanpa data hidup.
